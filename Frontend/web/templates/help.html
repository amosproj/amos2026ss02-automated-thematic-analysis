Getting Started

The Automated Thematic Analysis tool simplifies the qualitative research process into three main steps:

  1. Upload your data: Head over to the Transcripts page to securely upload your interview texts. Optionally, attach metadata via the Demographic Data section.
  2. Generate a Codebook: On the Codebooks page, you can instruct our LLM to automatically generate a hierarchical theme-structure from your corpus, or you can build/upload one manually.
  3. Run the Analysis: Navigate to the Analysis workspace to apply your Codebook across all documents. The system will extract specific quotes and link them to themes for easy review.

Frequently Asked Questions

By default, the application connects to the NHR@FAU cluster. The Home page also lists every server-configured provider, including OpenRouter with OpenAI GPT-5.6 when an OpenRouter API key is configured. The selected provider handles AI generation and analysis tasks.

The included OpenRouter profile uses openai/gpt-5.6-sol for chat and openai/text-embedding-3-small for embeddings. To replace the chat model, set LLM_MODEL_OPENROUTER in Backend/.env to an exact provider-qualified model ID from OpenRouter.

To offer several OpenRouter models as separate Home-page choices, add named settings and a ProviderSpec for each reviewed profile. Recreate the API container with docker compose up -d --force-recreate api after changing its environment.

An embedding model converts short pieces of text, such as code labels and descriptions, into numeric vectors so the system can compare their meaning. The Traceable Analysis algorithm uses embeddings to find similar or duplicate codes during codebook generation and consolidation before asking the LLM for deeper reasoning. Other generation algorithms decide which models, if any, they use.

Your transcripts are stored in the database configured by the server operator. When an operation uses chat generation or embeddings, the relevant text is sent to the LLM provider selected on the Home page. The Keyword Frequency demo generates its codebook locally without an LLM, although applying that codebook to transcripts still uses the selected provider.

Copy the supplied example.py template ↗, implement its asynchronous generate() method, and keep the create() factory. The backend continues to handle loading documents, jobs, cancellation, validation, persistence, and provenance.

Set GENERATION_ALGORITHM in Backend/.env to make one local algorithm the server default, or add an AlgorithmSpec in Backend/app/generation/registry.py to expose it as an additional named choice. Recreate the API container, then select it under Codebook Generation Algorithm on the Home page.

The system automatically links a row when its username matches a transcript title, ignoring capitalization and surrounding whitespace. You can review, change, or create links manually on the Linking page.

A Manual Codebook is built by you from scratch, giving you direct control over its hierarchy and definitions. A Generated Codebook is created from selected transcripts by the generation algorithm chosen on the Home page. Traceable Analysis uses an LLM and embeddings; the Keyword Frequency demo illustrates the extension interface without using an LLM for generation.

Generation and codebook application time scale with the number and length of the selected transcripts. Algorithms that make several LLM or embedding requests, such as Traceable Analysis, also depend on the selected provider's response time. Select fewer transcripts when appropriate, or choose a faster configured provider or generation algorithm.

The platform displays Token Usage for runs that call an LLM. Use the pricing published for the exact model and provider selected on the Home page. If prices are quoted per million tokens, calculate (input tokens / 1,000,000) × input rate + (output tokens / 1,000,000) × output rate. The Keyword Frequency demo uses no LLM tokens while generating a codebook; applying the result can still use LLM tokens.

When at least three transcripts are selected, Traceable Analysis uses part of the corpus to discover themes and holds out the rest to evaluate and refine the codebook against unseen text. Other generation algorithms can use a different process.

By default, the requested held-out ratio is 20%. The number of whole documents is rounded, with at least one document held out when this feature applies.

How to change this: Set TRACEABLE_HELDOUT_RATIO in Backend/.env, then recreate the API container. Set it to 0 to disable the held-out split.
